# VHH 四项问题处理过程（2026-09-13）

## 范围与停止规则

处理端部识别定位、软条件/序列阶段、短肽评价校准、同候选删除比较四项问题。只用现有权重推理，不训练、不转 BindCraft、不无限重试。GPU 串行；校准 2 次，900 秒硬限；只有真实 2/2 恢复才执行后续。后续固定为配对 24 次（1800 秒）和原始/改写序列 8 次（900 秒），没有看到结果后增加抽样。

## 实际过程与纠正

1. 重新核对原始生成、序列改写、自由复核三个阶段。首次诊断 attempt01 未识别 IF 侧链占位，已被 attempt02 取代，保留私有历史，不作为发布证据。
2. installed writer 明确为 IF 添加零坐标侧链。新诊断把这些输入的 CDR 重原子接触设为不适用；不会把不可评价写成零。C 原始生成实际为 1/2 双端接触；不能据此认定序列改写造成结合丢失。
3. 已知短肽结构选择记录：6I2G/5IVN 有非标准端部；8JLY 缺重原子；拒绝悄悄标准化。采用实验 9NK9，全长 10 aa 已建模肽，VHH 使用连续 118 aa 已建模部分，缺少的原序列两端共 14 aa 明示，不补原子。不是 GLP-1 对照或生物阴性。
4. 配对 preparation01 因截短后的 atom_site.label_seq_id 仍为 3..30、序列实体为 1..28 而真实 CPU 解析失败。新适配器只修改新建派生输入编号。preparation02 保留；preparation03 同时明确非零标签不全是正 hotspot，作为最终蓝图。六个候选两状态共享坐标及序列身份被逐一检查。
5. ARG 的 NH2 是侧链胍基氮，不是 C 端酰胺。当前 canonical 路径不能核实 C 端酰胺、N 端电荷；未伪造原子或声称化学已解决。比较限定为“同候选、几何匹配的两残基删除”。
6. 短肽代码提交 20f4643 后在独立、干净的 detached checkout 执行；诊断/配对代码提交 0ea926a 后同样冻结。这样允许报告与其余 CPU 开发并行，不放宽 clean-repository 检查。GPU 使用的源文件哈希冻结于输入/执行计划。
7. 9NK9 GPU 两次均恢复：1.9808 / 2.1882 Å；原生接触恢复 30/38、28/38。总执行 55.889 秒，包括启动、校验与评分；不是纯 CUDA 时间。权重前后未变。随后先执行已准备好的配对组，原始/改写序列准备同时在 CPU 完成；次序改变不改变候选或阈值。
