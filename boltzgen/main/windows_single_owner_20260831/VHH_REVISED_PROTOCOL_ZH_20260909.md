# VHH 线修订方案：先检验识别机制，再扩大设计

本方案对应 2026-09-09 用户确认的六项改进。代码和规则已实现不等于四个阶段已运行；实际状态以新运行收据和 `vhh_stage_gate.py` 输出为准。旧 T11/T12 输入、结果、阈值及当时的通过/失败记录保持不变。

## 目标和证据边界

目标是提出优先识别 **活性 GLP-1(7–36)NH₂**、减少识别 **截短 GLP-1(9–36)NH₂** 的 VHH（纳米抗体）计算假说，不是只让两个分子靠近，也不是药效验证。His7、Ala8 是活性版本开头、截短版本缺失的两个残基。

人工刚体摆放的高接触参考姿态不是实验复合物。偏离它只能说明没有重现该姿态，不能独自证明“没有结合”。同样，接触、低 RMSD、高 iPTM 或较好排名均不是结合、亲和力、选择性或可开发性的实验结论。阶段 `COMPLETE` 仅表示技术工作及其检查完成；本方案没有生物学 `PASS`。

## 六项具体修改

| 修改 | 本轮实施规则 | 禁止的错误解释 |
|---|---|---|
| 1. 对准识别机制 | 原子身份验证后计算 CDR–目标界面、His7/Ala8 接触、重复预测界面一致性；参考姿态 RMSD 降为次级描述 | 用偏离人工参考位置否定结合；把接触阈值当亲和力阈值 |
| 2. 分开设计和检验 | 受约束设计与自由复折叠独立记录；自由检验不输入原生跨链相对几何；实际读取的模型配置写入收据 | 把强制摆好的结合位置当独立验证；打开没有训练过的条件开关 |
| 3. 增加已知对照 | 在扩展设计前，用已知良性 VHH–抗原复合物做真实 GPU 自由复折叠，事前固定几何校准条件 | 把 CPU 原结构自检、读取成功或单一最好样本当校准通过 |
| 4. 恢复活性/截短配对 | 对完全相同的新候选，匹配推理条件比较两个核心状态；端部化学状态显式记录；GLP-2 为次级对照 | 新序列继承旧序列证据；把多个同源构象当独立负靶标；用原始 iPTM 差值直接声称选择性 |
| 5. 小规模多样化 | 校准完成后至多 12 个候选，覆盖 2–3 框架、至少两类 CDR3 和两类设计姿态；同步报告开发风险 | 在同一姿态上不断增加 seed；把序列变化误认为结构策略多样性 |
| 6. 节省时间且可追溯 | 每轮一个问题、明确预算与停止条件；候选为汇总单位；只核验变化输入并复用已验证原子映射 | 把 6 候选×5 次预测写成 30 个独立候选；反复全量审计不变的大文件 |

接触定义使用真实化学原子槽、去除氢的预测坐标，距离 ≤4.5 Å；不能误用参考 `resolved` 掩码丢掉已经预测出来的 CDR 侧链。RMSD 则按各自定义使用可对应的参考原子。接触阈值是描述规则，不是经过实验验证的筛选阈值。发生过近接触时还需报告几何/碰撞风险，不能用更短距离代表更强结合。

T12 的 target 与 framework 分属两个模板槽，不编码它们的相对位姿；当前复折叠检查点不消费 `BINDING` 条件输入。因此，本修订不把 T12 改名为“端部定向约束成功”，也不启用未经对应训练的条件分支。若比较模板机制，需考虑模板槽数变化这一伴随因素。

端部化学可标记 `ATOMICALLY_VERIFIED` 或 `NOT_ATOMICALLY_VERIFIED`；后者允许明确标注的探索运算，但不允许选择性结论。核心比较应关注游离 N 端和 C 端酰胺是否实际建模。1D0R 的构象来自三氟乙醇/水条件；不同来源分层汇总，不把其全部构象当独立生理样本。已经用于调参的锁箱只算开发负对照。

开发风险包括异常/未配对半胱氨酸、暴露疏水区域、极端电荷、序列组成和框架完整性；它们都是风险提示。研究重心仍是捕获/识别用途，不借此宣称安全性或成药性。

## 执行顺序和硬预算

| 阶段 ID | 问题与预算 | 完成条件／停止规则 |
|---|---|---|
| `existing_fold_reassessment` | CPU 重用已有 T11/T12 共 60 个预测；不重新推理 | 全量样本身份、映射、有限数值和候选汇总通过；明确标记事后分析 |
| `native_free_refold` | 已知复合物，恰好 2 个真实 GPU fold，最多 15 分钟 | 两次都符合事前冻结的工程几何校准条件；无原生跨链模板；超时/失败停止，不扩样 |
| `diversified_pilot` | 校准通过之后至多 12 个新候选，GPU 最多 30 分钟 | 多样性轴、唯一序列、完整输出和开发风险已报告；无自动追加 seed |
| `active_truncated_pairing` | 同一批至多 12 候选×2 核心状态×2 folds，至多 48 folds、GPU 最多 30 分钟 | 完整配对、相同候选及设置、端部状态和候选层面统计；结果仍是计算探索 |

这些是上限，不是必须耗尽的预算。预计无法在上限内完成时应缩小批次或停止，不能把未完成样本冒充完成。一次只有一个 GPU 主任务；OOM、NaN/Inf、缺文件、映射错误、校准失败或输入绑定不一致即停止相应阶段。对照失败时先排查评价器，不自动进入新候选设计、不切换 BindCraft、不训练或改写权重。

每次 GPU 运行前后，对真正使用的权重资产各校验一次摘要；不扫描未使用的检查点、不反复全树哈希。CPU 几何重评不加载权重，无需为其重新校验大权重。所有新运行写新目录，不覆盖历史数据。公开 GitHub 只提交脚本、配置、测试和小型脱敏摘要，不提交完整序列集、原始运行目录、权重或凭据。

## 可执行阶段门

协议为 [`configs/vhh_revision_20260909.json`](configs/vhh_revision_20260909.json)，判定器为 [`scripts/vhh_stage_gate.py`](scripts/vhh_stage_gate.py)。该脚本只读取收据并输出下一步，不启动 GPU、不创建运行结果。

```bash
python scripts/vhh_stage_gate.py \
  --contract configs/vhh_revision_20260909.json \
  --bindings /absolute/private/INPUT_BINDINGS.json \
  --receipts /absolute/private/EXISTING_FOLD_REASSESSMENT_RECEIPT.json
```

路径从本文件目录解释。私有 `INPUT_BINDINGS.json` 以阶段 ID 为键，每项记录该阶段输入、源码/配置及模型身份的小型清单。摘要使用 `vhh_stage_gate.digest` 的规范 JSON SHA256，不是文件排版字节哈希。新候选生成完成后记录输出候选集 `candidate_set_sha256`，配对阶段必须引用相同候选集；这项输出身份不是事前已知的序列、不能写成预注册候选。候选/状态设置变化必须更新绑定；模型及校准配置变化同样使旧校准不能复用。日期老旧本身只提示，不触发无意义重跑。

每个阶段收据包括 `schema=VHH_STAGE_RECEIPT_V1`、`protocol_id`、`protocol_sha256`、`stage_id`、`input_binding_sha256`、`status=COMPLETED`、协议指定 `evidence_kind`、`registration`、带时区的完成时间、`actual` 和逐项 `checks`。GPU 阶段另有事前登记时间、启动时间和 `actual.execution_device=cuda`。必须明确 `biological_pass=false`。CPU 60 样本重评是事后分析，不能伪装预注册。

收据还必须提供 `result_artifacts: [{"path": "绝对路径.json", "sha256": "原始文件字节SHA256"}]`，阶段门实际核对这些小型结果文件；不接受没有真实结果文件支撑的完成收据。原生校准的 `binding.calibration_thresholds` 及 `receipt.calibration.thresholds` 必须与协议一致，`receipt.calibration.samples` 必须包含样本 0、1 的实测数值，逐个满足：target 对齐后的 VHH Cα RMSD ≤5 Å、原生重原子残基接触对召回率 ≥0.3（两者均通过、2/2）。召回率使用 4.5 Å 接触定义，不是标准 DockQ。它们是这次小型流程校准的工程规则，不是普适生物学阈值。

`READY` 表示仅下一阶段可按其预算准备执行，**不是结果通过**；`BLOCKED` 表示已有收据缺失必需证据、失败或输入/配置不匹配，禁止下游 GPU；`COMPLETE` 也不允许生物学结论。门检查收据的一致性，真正的数值检查仍由阶段评分器完成；哈希防止误复用，不是对伪造收据的安全认证。
