## 1. 结论先行

本项目当前采用的是：

```text
冻结预训练权重
→ 审计输入数据
→ 小规模推理
→ 用计算代理评估
→ Agent 在严格白名单内小步调整
→ 保留同期 baseline 再比较
→ 配置冻结
→ 一次性 lockbox 群体检查
→ 才决定是否进入真实实验
```

这条路线可以用来发现输入错误、工程故障、结构不稳定、明显脱靶风险和配置退化，
并据此剔除明显计算风险、安排实验优先级；是否真正提高实验命中率或候选质量，必须
由后续配对实验验证。它不能在 AI 内部自证真实结合、亲和力、选择性、表达或稳定性。

必须始终区分三件事：

1. **不训练模型**：BoltzGen 权重不更新，不做反向传播，不用本项目数据拟合基础模型参数。
2. **AI 验证不是真值验证**：iPTM、PAE、RMSD、接触、clash 等都是计算代理，不是 `K_D` 或 binder/nonbinder 标签。
3. **M0 不是候选成功门**：M0 只证明资产身份、结构可解析性、重复关系、用途和标签语义可审计。

一句话口径：

> M0 PASS 表示“可以可信地开始后续 AI 技术验证”，不表示“AI 已设计出结合物”。

本文只定义接受合同，不自行签发 PASS。运行状态由仓库内的小型里程碑收据与外置
阶段收据共同表达；二者缺失或哈希不闭合时，状态必须保持
`M0_PENDING_EVIDENCE`。

## 2. M0 与 AIV0 的关系

`M0` 是项目管理里程碑，覆盖 AIV0 资产门及其仓库、路径和声明边界；它不是 AIV0–AIV4 之外新增的第六个 AI gate。

M0 的唯一目标是回答：

> 后续 AI 推理将读取哪些结构、每个结构代表什么、哪些是重复或隔离项、哪些可进入正靶/挑战/lockbox 分区，以及这些事实能否用哈希和机器清单复验？

M0 不回答：

- 某条 VHH 是否结合 GLP-1；
- 某条 VHH 是否不结合 GLP-1(9–36)、GLP-2、GIP 或 glucagon；
- 某个构象是否代表真实溶液布居；
- 某个计算分数是否对应实验亲和力；
- 后续 96–192 条实验面板是否应当放行。

## 3. 规范路径合同

### 3.1 URI 语义

| 前缀 | 解析基准 | 用途 |
|---|---|---|
| `repo://` | Git 仓库根 | 可提交的代码、合同、小型摘要、资源索引 |
| `workspace://` | Git 仓库的父目录 | 大型或受限数据、运行资产、完整登记册、本地报告和归档 |

进入 Git 的新文档、合同、公开 manifest 和规范 URI 字段，禁止写入用户名、盘符或机器绝对路径，也禁止使用 `~`、`$HOME`、`file://` 或未解析的路径通配符。`workspace://data/` 通常是历史兼容层；唯一明确保留的新 production 规范根是主合同已经广泛冻结的 `workspace://data/boltzgen_data/glp1_vhh_production_v1/`，不得再派生第三套 production 根。AIV0/AIV1 预检仍分别使用 `workspace://boltzgen/data/` 与 `workspace://boltzgen/runs/` 下的带日期只读根。

URI 必须在运行时由受控 resolver 解析。进入可追溯业务字段的资产身份应保存规范 URI、字节数和 SHA-256；运行器为重放命令或逐文件校验而记录的本机解析路径，只可留在受限外置 attempt 日志中，不得被当作 canonical 身份，也不得倒填进 Git 文档或公开 manifest。

## 4. M0 输入、输出与固定事实

### 4.1 输入类别

M0 只处理以下资产身份，不进行 BoltzGen 候选生成：

- GLP-1(7–36) 正靶参考几何；
- 1D0R 正靶 NMR 构象集合；
- GLP-1(9–36) 与 GLP-2 调参挑战结构；
- GIP 与 glucagon 一次性 lockbox 结构；
- 旧 12 个 production baseline VHH scaffold；
- 新 17 个待准入 scaffold 包；
- 每个文件的来源、用途、哈希、重复、完整性和隔离规则。

### 4.2 必须存在的 M0 合同与产物

Git 中的 V2 静态合同根至少包括：

```text
cohort_registry.tsv
file_overrides.tsv
asset_mounts.tsv
compatibility_aliases.tsv
historical_output_hashes.tsv
```

V2 外置派生登记册至少包括：

```text
source_file_inventory.tsv
structure_inventory.tsv
cohort_summary.tsv
duplicate_groups.tsv
scaffold_comparison.tsv
validation_summary.json
```

其中：

- `source_file_inventory.tsv` 回答“有哪些源文件、大小和哈希是什么”；
- `structure_inventory.tsv` 回答“每个 mmCIF 代表什么、是否完整、允许在哪个分区使用”；
- `cohort_registry.tsv` 回答“统计粒度是什么，哪些文件属于同一个来源/ensemble”；
- `file_overrides.tsv` 明确隔离、重复别名、固定对照和 scaffold 风险处置；
- `asset_mounts.tsv` 把规范资产 ID 映射到 `workspace://` 数据根，禁止从目录名猜身份；
- `compatibility_aliases.tsv` 只登记必须保留的历史兼容别名，并验证其最终解析目标；
- `validation_summary.json` 是机器放行摘要；
- 阶段 `receipt.json` 把 runner、validator、合同、登记册、日志和最终状态闭合成一次不可覆盖的 attempt 证据。

可另行生成供人阅读的报告，但它不能替代 `validation_summary.json` 和阶段 `receipt.json`。若报告参与决策，也必须进入 attempt 的 SHA-256 输入清单。

## 5. M0 通过门槛

### 5.1 当前冻结合同

M0 必须同时满足下表；只满足其中一部分不能写 PASS。

| 检查项 | 冻结要求 |
|---|---|
| schema | `AI_VALIDATION_ASSET_REGISTRY_V2`；V1 只作历史对照 |
| 总状态 | `overall_status=PASS`；`errors=[]`；`warnings=[]` |
| 规范挂载 | `asset_mounts.tsv` 中的每个 canonical `workspace://` 根可解析，逻辑路径唯一 |
| 兼容别名 | `compatibility_aliases.tsv` 中的别名全部指向登记的 canonical 根；未登记别名不得进入任务 |
| 源清单口径 | 177 条历史逻辑记录，合计 14,884,156 B；去掉 2 个 Finder 元数据后为 175 条逻辑文件，二者都不是独立科学样本数 |
| 结构路径 | 112 个 mmCIF，112/112 可解析 |
| challenge prepared CIF | 36 个 |
| 可用 challenge | 32 个构象，但只属于 4 个 target/source groups |
| challenge 隔离项 | 4 个不完整构象，任务数必须为 0 |
| 实验负标签 | 0；`no_binding` 目录名不得派生标签 |
| 1D0R | 1 个独立 NMR deposition、20 个相关构象；compact 只用 models 10/12/19/20 |
| 1D0R 别名 | 3 个 representative coordinate aliases，执行任务数为 0 |
| 新 scaffold | 17 个包；与旧 12 重叠 4 个 INSTANCE；并集 25 个唯一 INSTANCE |
| 新 scaffold production | active=0；隔离 2；repair-or-accept 4；待 canonicalize/check 7 |
| scaffold 清单 | 72/72 checksum entries、17/17 YAML 相对引用通过 |
| 化学边界 | C 端酰胺没有被当前坐标原子级证明；结构用途保持 `geometry_only` |

正文不写死 validator 或登记文件的 SHA-256，因为代码或合同的任何经审查修订都会使静态数字失效。当前 attempt 的真实指纹必须由 `validation_summary.json`、`inputs.SHA256SUMS`、`outputs.SHA256SUMS` 和最终 `receipt.json` 动态闭合；收据中的 manifest 哈希复算不一致即 FAIL。

SHA-256 能发现字节漂移，但不能单独证明来源许可、生物学正确性或文件没有被错误分类；这些问题仍由来源清单、mount 合同和语义规则共同约束。历史 20260826 V1 哈希不得复制成 20260828 V2 的接受证据。

### 5.2 M0 验证行为

正式 campaign 开始前，必须通过规范 AIV0 阶段运行器建立全新的 `attempt_NNN`。
新日期 V2 登记册的首次初始化可在已审查合同下使用一个显式
`--mode write` attempt，但只能写 Git 外的新 V2 派生目录；历史 20260826 V1 永久
只读。初始化之后必须用新的 attempt 执行 `--check`，最终放行只接受该只读
`check` 收据。禁止为了让检查通过而覆盖历史输出、改期望计数或移动源文件。

只有以下证据同时闭合，M0 才能写 PASS：

1. `receipt.json` 为 `AIV0_STAGE_RECEIPT_V1`，`status=PASS` 且 `exit_code=0`；
2. validator 的机器输出为 `AI_VALIDATION_ASSET_REGISTRY_V2`，并满足 5.1 的全部门槛；
3. `inputs.SHA256SUMS` 至少绑定 runner、validator、迁移收据、源资产根 manifest、五个 V2 静态合同文件；派生登记文件由 `derived_outputs.SHA256SUMS` 逐文件绑定；
4. `outputs.SHA256SUMS`、输入清单和收据所记录的 manifest 哈希可独立复算；
5. attempt 目录位于仓库外、首次创建且最终收据最后原子发布；缺失收据、复用 attempt 或只有终端截图均视为未通过。

本机绝对路径只能由操作者在运行时提供，并只能出现在受限的外置 attempt 日志中；它们不得写回本文、Git 合同或公开 manifest。

出现有意新增数据或政策变化时，应：

1. 保留旧登记册不变；
2. 建立带新日期或版本的新登记册；
3. 重新审核来源、许可、粒度、重复和用途；
4. 生成新哈希与 superseding 说明；
5. 从 AIV0 重新开始，不把新数据静默塞入旧 campaign。

### 5.3 M0 PASS 允许与不允许

M0 PASS 后可以：

- 准备并测试 AIV1 技术流水线；
- 依据显式 allowlist 构造非 lockbox 的候选×结构任务矩阵；
- 建立 append-only AI 经验库；
- 继续完成 Linux/NVIDIA 环境门和小规模技术验收。

M0 PASS 后仍不允许：

- 更新 BoltzGen 权重或训练 binder/nonbinder 分类器；
- 把新 17 scaffold 直接加入本版 12,000 production；
- 生成或查看候选×lockbox 结果；
- 把目录名、构象数或计算分数写成实验标签；
- 宣布存在 binder、nonbinder、`K_D` 或已证实选择性；
- 自动授权 96–192 条全面板实验。

## 6. AIV0–AIV4：给非专业用户的解释

| Gate | 做什么 | 通过代表什么 | 不代表什么 |
|---|---|---|---|
| AIV0 资产门 | 审计文件、结构、重复、分区、隔离和标签语义 | 数据身份及用途可复验 | 模型有效或候选结合 |
| AIV1 技术门 | 用 10 个冻结 anchor 跑完整非锁箱多状态评价链 | 任务矩阵、原子映射、指标、失败码和经验库可重放 | 命中率或跨 scaffold 泛化 |
| AIV2 覆盖门 | 跑 240 baseline；必要时最多两个同期 baseline+variant 比较轮 | 选择保留 baseline 或一个有限配置变体 | 在同一挑战集上的改善能推广到真实实验 |
| AIV3 配置冻结门 | 用选定配置跑 2,400 条诊断批并检查无退化 | 是否允许冻结配置后进入 12,000 生产采样 | 已通过独立盲测或已获得 binder |
| AIV4 一次性锁箱门 | 预冻结面板后，先跑 full 1D0R sensitivity，再一次性打开 GIP/glucagon 候选结果 | 当前 campaign 是否通过计算风险筛并可物化同一全面板 | 真实结合、真实选择性或个体候选排名真值 |

关键分母：

- AIV1：10 个候选、160 个 logical tasks、800 个 sample rows；
- AIV2 baseline：240 个候选、3,840 个 logical tasks、19,200 个 sample rows；
- 每个 AIV2 variant 比较轮：240 baseline + 240 variant，共 7,680 个 logical tasks、38,400 个 sample rows；
- AIV3：2,400 个候选、38,400 个 logical tasks、192,000 个 sample rows；
- AIV4：预面板大小 `P=96–192`；full sensitivity 为 `20P/100P`，lockbox 为 `P×21/P×105`。

缺任何应有任务时，不得只对已成功子集算一个更好看的平均值。

## 7. Agent 筛选—调整循环

### 7.1 Agent 可以做什么

Agent 是受合同约束的执行与决策代理，不是实验真值来源。在 AIV2–AIV3 允许范围内，它可以：

1. 读取上一 campaign 的完整、哈希闭合证据包；
2. 先按失败类型归因，再查看连续指标和分层分布；
3. 提出一个可以被数据推翻的假设；
4. 从冻结 `allowed_adjustments` 中选择最多 1–2 个变量；
5. 在运行前冻结配置差异、预期方向、最小改善、guardrail、预算和停止条件；
6. 同期保留不变 baseline，运行新 campaign；
7. 按预注册规则选择接受、回退或停止；
8. 把成功、失败、不确定和理由全部追加进经验库。

默认可调整项只限预定义版本，例如 binding-site token、CDR 设计范围、工程安全的 sampling budget/batch 和结构过滤规则版本。新增权重、改变标签定义、修改 raw 结构、放宽分母、删除失败候选、改变目标化学身份或授权实验，均超出 Agent 权限。

### 7.2 为什么“不训练”仍会过拟合

权重不变并不等于没有过拟合。Agent 若反复根据同一个 tuning challenge 改配置，相当于不断练同一套题：该套题分数可能上升，但真实实验或新靶标不一定改善。

因此必须同时保留：

- 固定且同期运行的 baseline；
- 最多两个 config-variant 比较轮；
- 每轮最多 1–2 个预注册变量；
- 运行前冻结的接受规则；
- 不可用于调参的一次性 lockbox；
- 最终真实正靶/负靶配对实验。

### 7.3 接受 variant 的最低规则

variant 只有同时满足以下条件才可替代 baseline：

- 所有 hard guardrail 不劣于 baseline；
- 至少一个 primary AI metric 达到预注册的最小改善；
- 分层不确定区间不与“无改善或不可接受退化”冲突；
- 完整率、序列多样性和高严重度失败不恶化；
- 没有数据泄漏、规则漂移或静默丢行。

如果不同指标互有胜负且没有预注册的支配规则，结论必须是 `INCONCLUSIVE_KEEP_BASELINE`，不能由 Agent 临时发明权重挑选喜欢的结果。

## 8. 必须停止的情况

| 触发条件 | 必须动作 |
|---|---|
| 任一输入、权重、代码、环境或登记哈希漂移 | `BLOCKED_INPUT_OR_ENVIRONMENT_DRIFT`；不得继续推理 |
| 目录名、构象数或 proxy 被当成 0/1 实验标签 | `BLOCKED_LABEL_SEMANTICS`；停止并纠正数据合同 |
| baseline 缺失、预算不等或比较分层不一致 | 当前比较无效；不得接受 variant |
| 评价公式、阈值、聚合或停止条件在看结果后变化 | 当前 comparison 作废；建立新方案版本 |
| 应有任务、sample 或失败分母不完整 | `TECHNICAL_INCOMPLETE`；不得从子集作科学判断 |
| 两个允许的 AIV2 variant 已用完仍无明确改善 | 保留 baseline 或写 `STOP_BEFORE_12000`；禁止继续试配置 |
| hard guardrail 退化、严重失败增加或多样性坍缩 | 回退 baseline；必要时停止 campaign |
| AIV3 工程门或 AI 无退化门失败 | `STOP_BEFORE_12000` |
| 12,000 生产开始后提出科学配置变化 | 终止当前 campaign；旧结果只读；返回新 AIV2/AIV3 campaign |
| AIV4 前出现任何候选×lockbox 结果 | 当前 lockbox 失效；登记访问并为新 campaign 取得独立 lockbox |
| full 1D0R sensitivity 不完整或 FAIL | 不开 lockbox；不得换面板后重试 |
| GIP 或 glucagon 任一为 `FAIL`、`INCONCLUSIVE` 或 `TECHNICAL_INCOMPLETE` | 不放行 96–192 条全面板 |
| Agent 试图改权重、标签定义、raw 结构或授权实验 | 停止自主循环，提交负责人和新方案版本 |
| 任何人在实验前声称 binder、`K_D` 或真实选择性 | 停止该声明；只能写“计算风险代理” |

AIV4 失败时，只有数据完整、无泄漏且负责人另行批准，才可使用开箱前预冻结的 8–16 条 sentinel 开展独立 `CALIBRATION_SENTINEL_ONLY` 实验。它不是 AIV4 PASS，也不能扩成全面板。

## 9. 成功/失败经验库

### 9.1 目的和边界

经验库用于：

- 避免重复已知无效配置；
- 复用已经证实的工程修复；
- 追踪同一失败在新 campaign 是否消失；
- 让每次 Agent 决策可复查、可回放；
- 保留失败分母，防止只看成功候选。

经验库不是训练集。实验前写入其中的计算事件不能连接成 binder/nonbinder 标签；实验标签只能进入独立实验 registry，并通过不可变 candidate/sequence key 受控连接。

AIV0 的正式运行根已经由 `attempt_007` 冻结，禁止再向其中追加 AIV1 文件。AIV1 正式经验库的规范外置位置改为新的 production campaign 根；AIV1 预检证据使用另一个独立根：

```text
workspace://data/boltzgen_data/glp1_vhh_production_v1/07_analysis/ai_validation/ai_experience_registry.sqlite
workspace://data/boltzgen_data/glp1_vhh_production_v1/07_analysis/ai_validation/ai_experience_events.jsonl
workspace://boltzgen/runs/glp1_vhh_aiv1_preflight_20260828/logs/stages/aiv1_readiness_preflight/attempt_NNN/
```

这些运行资产不进入 Git；Git 只保存 schema、代码、合同和经过许可/隐私审查的小型摘要。AIV1 的 handoff（阶段交接）收据必须只读引用 AIV0 `attempt_007` 的 SHA-256，不得复制后改写 AIV0 事实。

### 9.2 最低结构

| 实体/事件 | 记录什么 |
|---|---|
| `asset_snapshot` | 本次 campaign 使用的数据登记册和哈希 |
| `campaign` | campaign ID、类型、输入快照和创建时间等不可变身份；状态变化进入 `campaign_event` |
| `config_snapshot` | 规范配置、配置哈希及相对父配置的差异 |
| `candidate` | 候选 ID、完整序列哈希和谱系哈希 |
| `task` | 候选×目标×构象任务和期望样本数等不可变身份；重试/完成状态进入 `task_attempt_event` |
| `sample_result` | 每个 task/fold/sample 一行；完整 AIV1 必须精确为 800 行 |
| `metric_sample` | 指向 `sample_result` 的逐指标长表；行数为 `800 × 指标数`，不作为 800 行分母 |
| `metric_ensemble` | 在正确 independence group 内聚合后的指标 |
| `failure_event` | 主失败码、次失败码、证据哈希和归因置信度 |
| `codex_decision` | 输入证据包、接受/回退/停止、理由和允许变化 |
| `lockbox_access_intent` | 不可回滚的开箱消费事实及候选/矩阵/config 哈希 |
| `lockbox_access_completion` | 期望与完成 task/sample 分母及完成收据 |
| `artifact` | 产物角色、规范 URI、字节数和 SHA-256 |

每个成功/失败经验事件至少还应含 `event_id`、`campaign_id`、`stage`、`result_class`、`hypothesis`、`changed_variables`、`baseline_config_sha256`、`variant_config_sha256`、`evidence_receipt_sha256`、`primary_failure_code`、`guardrail_result`、`decision`、`reason`、`created_at_utc` 和可选 `supersedes_event_id`。其中 `result_class` 只能取 `SUCCESS`、`FAILURE`、`INCONCLUSIVE` 或 `TECHNICAL_INCOMPLETE`，禁止把技术失败改记为科学失败。

### 9.3 不可变规则

- 历史 campaign、task、config、metric、failure、decision 和 lockbox 事实禁止 `UPDATE` 或 `DELETE`；状态转换通过 append-only（只追加）事件表达；
- 更正通过追加带 `supersedes_event_id` 的新事件表达；
- 技术重试使用稳定 operation ID，不能生成新的随机科学条件；
- 每个 receipt 必须绑定输入、模型、代码、环境、预算、期望/完成/失败分母、配置差异、输出树和数据库事务哈希；
- 全部成功、失败、不确定和技术不完整都必须入库。

| SHA-256 | 把文件字节映射成固定长度十六进制指纹的哈希算法 | 可检测字节漂移；不能单独证明许可、来源或科学正确性 |
| anchor | 在 G2 通过后冻结、供 AIV1 验证评价链的锚定候选；本版精确为 10 条 | anchor 不是实验阳性，也不代表“最佳候选” |

| builder | 按冻结输入和规则确定性生成任务矩阵/清单的脚本 | builder 只“造任务表”，不运行模型，也不能伪造缺失候选 |
| runner | 按顺序调用阶段、保存日志并最后发布 receipt 的运行脚本 | runner 必须保留失败 attempt，不能覆盖旧结果 |
| validator | 只读核对输入、输出、数量、字段和哈希是否满足合同的验证脚本 | validator 不应修复或刷新被验证的数据 |
| schema | 数据文件或数据库允许哪些字段、类型、约束和关系的结构合同 | schema 改变会改变解释方式，必须版本化并重新签发证据 |

| JSON | JavaScript Object Notation，使用键和值保存层级数据的文本格式 | 字段名、类型和规范编码都属于哈希合同，不能任意增删 |
| TSV | Tab-Separated Values，使用制表符分列的文本表格 | 表头、列顺序、行数和换行方式都可能被 receipt 冻结 |
| CSV | Comma-Separated Values，使用逗号分列的文本表格 | 必须同时核对表头、行数、唯一 ID、缺失值和哈希，不能只用表格软件打开查看 |
| NPZ | NumPy 的 ZIP 压缩数组文件；一个文件可保存坐标、评分和原子映射等多组数组 | 本项目以 `coords` 第 0 维的 5 个切片作为 5 次折叠样本，不能把单个 Writer CIF 复制成 5 行 |
| handoff | 一个阶段向下一阶段交接输入和授权的过程及其机器收据 | 只有上游证据/哈希闭合，handoff 才能授权下一门；复制文件不等于完成交接 |
| fail-closed | 证据缺失、冲突或无法验证时默认阻断，而不是猜测通过 | 允许出现 BLOCKED，但禁止用占位数据凑齐 160/800 |
| canonical | 在多个副本、别名或历史路径中被合同选定的唯一规范身份 | 新任务只引用 canonical URI，不从目录扫描猜文件 |
| ensemble | 同一来源或实验 deposition 下的一组相关构象 | 必须先组内聚合，不能把构象数当独立生物学样本数 |
| quarantine | 因缺失、冲突或高风险而隔离的资产 | 可保留审计，但执行任务数必须为 0，直至新版本正式解除 |
| receipt | 机器可读的阶段完成凭证，绑定输入、输出、状态和哈希 | 截图或口头说明不能替代 receipt |
| iPTM | predicted interface Template Modeling score，模型给出的复合物界面可信度代理 | 高 iPTM 不是结合或高亲和力证明 |
| PAE | Predicted Aligned Error，预测两个位置相对排布误差的矩阵 | 低 PAE 只表示模型更确定，不是实验真值 |
| RMSD | Root-Mean-Square Deviation，两个原子集合坐标差异的均方根 | 依赖原子映射和对齐方式，低值不自动等于功能正确 |
| `K_D` | 平衡解离常数，数值越小通常表示实验测得的结合越强 | 必须由 SPR/BLI 等实验得到，不能由 AI 分数替代 |
| SPR / BLI | 表面等离子共振 / 生物层干涉，两类实时测量分子结合的实验方法 | 本项目最终正负靶选择性需要这类配对实验 |
| scaffold | 保留主要框架、允许在 CDR 等区域设计的 VHH 起始骨架 | 新 17 个包尚未获 production 准入 |
| checkpoint | 一次模型训练后保存的权重状态；不同 checkpoint 可产生不同推理行为 | 本项目只读取冻结 checkpoint，不更新其权重 |
| guardrail | 不允许为了改善主指标而破坏的硬性安全/质量门槛 | 任一退化就回退或停止，不能临时改阈值 |
| logical task | 合同定义的一次候选×目标×构象评价任务 | 缺任务必须计入分母，不能静默删除 |
| sample row | 同一 logical task 下某次折叠/采样的明细记录 | 多行 sample 不等于多个独立生物样本 |
| manifest | 机器可读的资产清单，记录身份、路径、大小、哈希和用途 | 文件本体与 manifest 必须同时验证 |
| URI | Uniform Resource Identifier，统一资源标识符 | 本项目用 `repo://` 和 `workspace://` 避免本机绝对路径进入合同 |
| `AIV1_DATA_COMPLETE` | 证明同一版评价规则下 160/160 tasks、800/800 sample results 和失败分母全部闭合的收据 | 它不是 AIV1 最终放行；若 final spec 改变规范字段，必须对同一 160/800 重跑并重签 |
| `AIV1_HANDOFF_PASS` | final spec、最后一份 DATA_COMPLETE 和完整经验库 schema receipt 逐字绑定后发布的 AIV1 最终交接收据 | 只有该收据才授权进入 AIV2，仍不证明结合或选择性 |

### 13.3 AIV1 的两步关闭语义

为消除“先 AIV1 PASS、后冻结 `ai_eval_spec`”与“AIV1 必须交付冻结 spec”的时序冲突，正式实现采用两个收据：

1. AIV1 首次运行前先冻结 provisional spec（临时评价规则）；它只规定指标 schema（字段规则）、公式、方向、缺失处理、聚合顺序和失败语义，不冻结跨 scaffold 数值阈值。按它完成 160/160 logical tasks、800/800 `sample_result`、原子映射、指标、聚合、失败分母和 lockbox=0 后，发布与该 spec 哈希绑定的 `AIV1_DATA_COMPLETE`；
2. 查看 AIV2 的 240 条结果前形成 final spec（最终评价规则）。若 final 相对 provisional 在 schema、公式、方向、缺失或聚合任一规范字段改变，旧 DATA_COMPLETE 只保留为历史证据，必须对**同一 10 anchors×16 states、同一 160 tasks/800 sample results**全量重跑，重新签发 DATA_COMPLETE 的输入、代码、spec 和输出哈希；禁止只重算子集；
3. `AIV1_HANDOFF_PASS`：只在 final spec、最后一次完整 160/800 DATA_COMPLETE，以及从 `AIV1_BOOTSTRAP_SCHEMA_PARTIAL` 到完整经验库 schema 的版本化 migration receipt 全部逐字闭合后发布。AIV1 不从单一 7XL0 cell 冻结跨 scaffold 数值阈值。

只有第二类收据 `AIV1_HANDOFF_PASS` 发布后才能进入 AIV2。两类收据都只代表技术链闭合，不代表 binder（真实结合物）、`K_D`（实验解离常数）或选择性。
